# GameDock · Windows-прототип

Это самостоятельный прототип локального Vanilla-сервера. Команды сборки и тестов запускаются из этой папки. Основное приложение GameDock находится в корне репозитория.

Один локальный сервер Minecraft Java Edition Vanilla 1.21.11 под Windows x64. GameDock готовит сервер, запускает и останавливает его, показывает журнал, импортирует мир копированием и восстанавливает резервную копию.

GameDock — экспериментальный проект для тестовых миров на одном ПК. Сервер слушает `127.0.0.1:25565` и проверяет учётные записи Minecraft. В первую публикацию входят исходники. Чтобы получить `GameDock.exe`, соберите проект на Windows по инструкции ниже.

**GameDock — неофициальный продукт для Minecraft. Mojang и Microsoft не одобряли этот проект и не связаны с ним.** Проект публикует команда GameDock. Для обращений используйте раздел Issues репозитория. [Правила использования бренда Minecraft](https://www.minecraft.net/en-us/usage-guidelines).

## Запуск

1. Установите Microsoft Edge WebView2 Runtime и Java 21 x64 из официальных источников. [WebView2 от Microsoft](https://developer.microsoft.com/microsoft-edge/webview2/#download-section) · [Eclipse Temurin 21 от Adoptium](https://adoptium.net/temurin/releases/?os=windows&arch=x64&version=21).
2. Откройте `GameDock.exe`, собранный из исходников. У локальной тестовой сборки нет цифровой подписи.
3. Прочитайте Minecraft EULA. Если принимаете её, поставьте отметку и нажмите «Загрузить сервер». GameDock скачает закреплённый JAR с официального адреса Mojang и проверит SHA-256.
4. Выберите `java.exe` из Java 21, оставьте 2048 МиБ для первой проверки и нажмите «Запустить».
5. Статус «Работает» появляется после ответа сервера на проверку игрового протокола. Затем подключитесь клиентом Java Edition 1.21.11 к `127.0.0.1:25565`. Для создания копии или восстановления сначала остановите сервер.

Если порт занят, остановите другое приложение, которое его использует. Закрытие окна сначала запрашивает штатную остановку. Если сохранение длится более 20 секунд, окно остаётся открытым, а JVM продолжает работать. В интерфейсе можно подождать ещё или отдельно подтвердить принудительное завершение. Принудительное завершение во время записи может повредить тестовый мир.

## Импорт и восстановление

- Для импорта остановите исходный сервер и выберите его корневую папку. Поддерживается мир `world` версии 1.21.11 с проверкой аккаунтов. Копируются файлы мира и списки игроков. GameDock создаёт локальные настройки запуска. Исходные JAR, настройки сети и EULA остаются в исходной папке.
- Корень данных по умолчанию — `%LOCALAPPDATA%\GameDock\Prototype`. Для отдельной демонстрации импорта задайте `GAMEDOCK_DATA_DIR` с абсолютным путём к новой пустой папке. Установки с разными корнями всё равно используют один и тот же порт.
- Обычные копии находятся в `backups`. При восстановлении GameDock готовит копию отдельно и переключает активную папку. Предыдущая папка остаётся в `recovery` с отметкой времени. После прерывания между переименованиями приложение возвращает прежнюю активную папку при следующем запуске.
- Папка `recovery` предназначена для ручного извлечения предыдущего состояния. Объём копий и их хранение пока контролирует владелец ПК.
- Для теста без доступа к CDN задайте `GAMEDOCK_SERVER_JAR` с путём к уже полученному официальному JAR. В обоих режимах GameDock сверяет файл с SHA-256, закреплённым в исходниках. [Адрес Mojang и ожидаемая контрольная сумма](internal/vanilla/install.go).

Храните рабочие данные и тестовые артефакты за пределами репозитория. Миры, резервные копии, журналы и списки игроков могут содержать данные вашей игры и учётных записей. Для сообщения об ошибке достаточно обезличенного фрагмента журнала и шагов воспроизведения.

## Сборка из исходников

Откройте PowerShell в папке этого файла на Windows x64. Используйте Go 1.26.10 или более новый патч ветки 1.26. При первой сборке Go скачивает зависимости. Файлы интерфейса уже входят в исходники и встраиваются в `GameDock.exe`. [Загрузка Go](https://go.dev/dl/).

```powershell
go test ./...
go vet ./...
go build -trimpath -buildvcs=false -tags=desktop,production -ldflags=-H=windowsgui -o GameDock.exe .
```

GitHub Actions проверяет исходники на Windows при push и в pull request. Ручной запуск доступен после добавления workflow в основную ветку. В проверку входят обычные тесты, `go vet`, проверка синтаксиса JavaScript и сборка. Тесты с официальным JAR запускаются отдельно, а сборка в CI служит только для проверки. [Конфигурация CI](../../.github/workflows/vanilla-local.yml).

Для теста повторной настройки с официальным артефактом задайте `GAMEDOCK_TEST_SERVER_JAR` и запустите `go test -count=1 -v -run '^TestRepairWithOfficialJar$' .`. Тест работает во временной папке и проверяет подготовку и повторную установку файла без запуска Minecraft.

### Сквозной тест с настоящим Vanilla

Тест использует свободный локальный порт 25565 и две временные папки. Укажите официальную сборку Vanilla 1.21.11 и путь к Java 21 x64. Устанавливайте флаг согласия только после принятия условий для тестового запуска. [Minecraft EULA](https://www.minecraft.net/en-us/eula).

```powershell
$env:GAMEDOCK_TEST_SERVER_JAR = 'C:\TestAssets\vanilla-1.21.11.jar'
$env:GAMEDOCK_TEST_JAVA = 'C:\TestAssets\java21\bin\java.exe'
$env:GAMEDOCK_E2E_ACCEPT_EULA = '1'
try {
    go test -count=1 -v -timeout=8m -run '^TestVanillaWorldRoundTrip$' .
} finally {
    Remove-Item Env:GAMEDOCK_E2E_ACCEPT_EULA
}
```
